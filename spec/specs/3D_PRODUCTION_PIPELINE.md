# 3D asset production, photorealism and website export

## Ground rules and asset traceability
All visuals must be legally usable in a commercial portfolio. Reference reel frames are for *style/interaction analysis only*. Never embed an actual copyrighted facade, reference video frame, company logo or unique floor plan as production art without permission. Favor an ORIGINAL Blender exterior and interior; CC0/clearly commercially licensed furniture/materials are allowed if source/license retained. Free does NOT necessarily mean commercial use permitted. Attribute every third-party library, model, HDRI, texture, icon, sound and font.

## Production stages
P0 Preflight: detect GPU/VRAM/CPU/RAM/disk and installed Blender version, browser/WebGL availability, version controlled repo, render engine supported. User context suggests PC Ryzen 5 3600 and RTX 3050, but probe actual machine; never assume GPU memory quantity. Select Eevee for iterations; Cycles for selective hero renders if feasible, use samples/noise controls appropriate to available hardware. If Blender absent and installation is safe, select official installation workflow for Windows; installation requires responsible permission when modifying system outside project.
P1 Single-source architecture: generate parametric building shell from floor grid, facade modules, elevators/stairs/service volumes, level IDs. Explicit naming: BLDG_L02_FLOOR_PICK, UNIT_L04_A_ZONE, SURFACE_UNIT_A_LIVING_FLOORING, etc. Do not create hundreds of ambiguous "Cube.001" objects. Validate number of levels and height invariants with script.
P2 Signature exterior: detailing at 3 scales: silhouette, medium-scale bands/shades/recessed balconies, micro-details at camera proximity: realistic window mullions, seams, handles, slab edges, drips, landscaping and architectural lighting. Even large forms must avoid toy-like proportions.
P3 One accurate typical residential floor: create occupancy zones, core and two coherent unit plans. Output clean top view, floorplate and dollhouse, link same dimensions to facade window grid. Hero Type A detailed: believable furniture, circulation, fitted cabinetry, bathroom fixtures, kitchen joinery, balcony railing. Type B visually distinct at moderate fidelity. No invisible room geometry posing as complete room.
P4 Two amenity floors: wellness with gym equipment, reception, pool deck, water plane and plausible plant/service zone; upper dining with kitchen, service, café counters, tables and separate shisha terrace zone subject to feasibility. Provide 2D fallback exploration and at least one premium rendered scene per amenity.
P5 Physically based materials: 0-1 roughness/metalness, consistent UV scales, linear/sRGB texture correctness, orientation-specific normals, tile joint scale and wood grain direction. Validate tone mapping and hue matches across Blender and three.js (visually close; exact physically identical not assumed). Separate editable slots/mesh names and keep all swatches standardized.
P6 Lighting: exterior morning/afternoon and evening; interior warm/cool fixture layers, plausible daylight through actual apertures, contact shadows, AO judiciously, reflection probes/environment/HDRI if licensed, avoid light leaks and blown highlights. Consistent white balance, realistic bloom only if restrained.
P7 Animated cameras: define exact key camera bookmarks with target/orbit boundaries, 3D coordinate map, near/far/FOV, transition paths, easing; avoid geometry collision; matching 2D fade/cut fallback. Export original cinematic stills/screenshots and separate gallery renders.
P8 Export: .blend original source and reproducible Blender Python, metric geometry, Y-up conversion for GLB, consistent origin and pivots, LODs where necessary, GLB/glTF 2.0 scenes grouped logically (exterior, repeated level, hero unit, amenities), keep semantic object/material names where raycasting/editing uses them. Use tools such as glTF Transform only if verified trusted. Compress geometry/textures as supported, KTX2/Basis if beneficial and compatible, Draco/Meshopt when measured; ensure required decoders available and version matched. Verify in real browser.
P9 Optimization: instancing repetitive windows/balcony parts, texture atlases when material editability not broken, drawcall budgets derived from measured devices, preload first view only, lazy-load interior/amenities, asset unmount/disposal policy, control DPR and shadows by tier, on-demand rendering when no animation, avoid new material object on every click, no memory leak on switching floors repeatedly.
P10 Visual QA: compare Blender hero still vs browser screenshot from same camera direction, matching facade band, floor count, accent materials and window positions. Artifact tracking: preview render, viewport test, material slot list, GLB inspector report, texture bytes, drawcalls, fps, memory. Fix obvious intersections, clipping, repeated textures, unrealistic scale, reflections and light leaks. Only then proceed.

## Capture design
Each hero still must have composition notes: focal point, 35mm-ish/other chosen FOV, horizon, time of day, camera height and target. Shot schedule: (01) exterior three-quarter golden hour, (02) front daylight architectural, (03) evening facade, (04) lobby, (05) cutaway typical floor, (06) unit A dollhouse, (07) living wide, (08) kitchen 3/4, (09) bedroom, (10) bathroom, (11) balcony, (12) pool, (13) gym, (14) wellness lounge, (15) rooftop café, (16) restaurant, (17) separate terrace. A scene photograph can be a render; never pass it off as actual built property photo. Respect visual consistency, color grading and appropriate sizes/compression.

## Material and image synchronization
Create a package snapshot matrix: e.g. Warm Ivory Standard, Walnut Premium and Pearl Signature. Pre-render chosen canonical schemes. Runtime change only modifies validated targeted scene materials and finish board. Switching to a photo gallery after arbitrary custom mix triggers notice or a generated true scene capture; do NOT represent a mismatched pre-render as exact current selection. Consider screenshot export at current WebGL camera for real state, with disclaimers about lighting/quality differences.

## Device tiers and fallback
Tier A: capable WebGL, full building + accurate room inspector (real materials).
Tier B: reduced geometry/textures/shadows/quality tier, still fully interactive floor navigation and selected materials.
Tier C: no WebGL, 2D floor map, gallery and material info/side-by-side pre-render packages; customization clearly marked as limited preview; all basic commercial actions available.
Choose numeric target budgets *after real profiling*. Baseline launch targets (not promises): Lighthouse performance >=80 desktop and >=60 mobile, accessibility >=90 where measurable, LCP <=2.5s on representative fast conditions, CLS <=0.1, responsiveness close to instant for material switch, 30fps+ on average mobile during static exploration where tested. If targets missed, show actual metric and remediation.

## Asset production acceptance gate
An asset passes only if (a) no license ambiguity, (b) semantically named, (c) dimensions/source-of-truth aligned, (d) realistic enough in target shots, (e) GLB import works, (f) interactive selection works, (g) memory/cpu acceptable, (h) fallback exists or error state describes limitation. Never call primitive boxes with flat colors "photorealistic completion".
