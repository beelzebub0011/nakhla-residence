# V3 — MULTI-MODE EXPLORATION + COMFORT-FIRST CAMERA CONTROL

## Four independently usable modes (single coherent scene/state architecture)
A. **Cinematic Tour / الجولة السينمائية**: optional crafted film-style 60–120-second guided narrative with editorial overlay and authored shots: exterior title, architectural flyby, selected floor glow, lift/separate floor, unit cutaway, enter room, material live swap, wellness, pool, sky restaurant, final contact. The experience should be skippable, pauseable, scrub-friendly if viable, muteable, with chapter list, quality-aware alternate shots, precise shot start/end frames, and immediate interruption to explore. It does NOT autoplay upon page load, hijack wheel scrolling, force soundtrack, or keep camera moving after user actively intervenes.
B. **Guided Tour / التجوال الموجّه**: navigable next/previous guided hotspots like professional architectural virtual tour; intuitive camera teleport or short linear glide room-to-room; on-screen room map, directional orientation, and optional explanatory tooltip per room. Works with single finger, mouse and keyboard; suitable for first-time consumers and low-motion users. Avoid excessive fisheye panoramas; no fake rooms represented as constructed spaces.
C. **Free Walk / التجوال الحر**: true bounded first-person movement inside genuinely modeled supported areas: desktop WASD/arrows + mouse-look only AFTER click-to-enter and clear escape; optional controller support; phone touch-look + optional minimal joystick, tap-to-move and hotspot targets; tablet touch equivalent. Collision/navmesh/doors/railings, camera eye-level, stairs/elevator transition as explicit destination, no walk-through-walls, speed limits and gentle acceleration, avoid camera bob, toggle sprint OFF by default, comfort height fixed. Accessible alternative guided hotspot path. Pause movement on modal/drawer; exit with persistent visible control or Esc.
D. **Property Explorer / مستكشف العقار**: reference-reel-style default experience: user orbits exterior, hovers/selects 12 levels, chooses 18 distinct unit IDs with repeated A/B models honestly, sees exploded floor/dollhouse, click-to-enter rooms and amenities, then materials, photo gallery and saved choices. Discrete task-driven transitions. Wheel scroll must remain normal page scroll unless 3D control was directly engaged; no scroll hijacking.
PLUS **Lite 2D Mode**: not treated as an inferior broken fifth mode; universally functional semantic building/floor/unit UI, interactive floor plans, gallery, materials, share/export and contact, with no WebGL dependence. It cannot claim true 3D freewalk. Option always available and automatic on unsuitable hardware/WebGL failure.

## Mode persistence contract
Use ONE centralized validated `ExperienceState` (mode, floorId, unitId, roomId, material overrides, weather, season, time, language, quality, cameraBookmark, playState, 2D fallback). Switching modes MUST NOT erase spatial/material/weather selections. Preserve last user camera per mode and per space; use explicit camera bookmarks. If navigation target incompatible (e.g. switching from F11 café to residential-only material studio), show an understandable transition choice; never silently teleport to unrelated Floor 01. Browser Back and deep links restore appropriate selection. Unavailable mode has clear explanation and nearest usable alternative. On any mode change, cancel prior animation, flush pending camera commands safely and avoid competing control loops.

## Comfort and interruption
- Never trap pointer lock; require user action, Esc exits, visible Exit Walk accessible in mobile and desktop; disable on touch environments where unsupported and offer tap-to-move.
- Camera movement: acceleration and braking continuous, angular velocity capped, no uncontrolled camera roll, spring overshoot or strong zoom. Short smooth transition default; setting for Instant transitions and `prefers-reduced-motion` overrides with cut/no zoom. Keep stable horizon and no shaky motion.
- Drag gestures: one-finger rotates or selects depending mode with clear tutorial, pinch zoom in orbit; two-finger pan optional, no conflicts with browser gestures and page scrolling. Portrait overlays do not consume entire viewport; UI hides/auto-dims gracefully.
- Collision mesh separated from render mesh, door openings validated, navmesh connectors for G / F01–F11, lift stops. True walkable rooms have door connection, reliable spawn/destination anchors and camera clearances. No invented unlimited navigability for unmodeled rooms; show guided still/gallery instead.
- When user activates a UI panel, suspend locomotion and keep camera stable. On close resume only after explicit intent when pointer lock is involved. Inputs not blocked by load; no offscreen canvas interaction ghost focus.
- Allow Reset View, Back to Unit, Jump to Floor, Open Mini Map, Help, Exit Mode (persistent), emergency 2D fallback. Adapt control help to input type.

## Camera implementation detail and quantitative evaluation
Define camera graph nodes, speed/angle limits, path length and room bounding volumes, navmesh walkable polygons, collision obstacles, portal transitions and saved anchors in the production scene manifest. Smooth the velocity rather than arbitrary frame-to-frame lerp; respect delta-time caps and loss-of-focus handling. RequestAnimationFrame/render-on-demand appropriate for active motion, pause expensive work when tab hidden. Use camera raycasting from cursor or explicit hotspot hitboxes, without event handling conflict with drag orbit. Avoid camera passing through opaque walls on transitions: use safe navigable waypoints, temporary accurate cutaway, or a clearly labeled instant scene switch.
Set provisional comfort targets during research; actual acceptance = real measured camera tests with no clipping, no loss of navigation, no perceptible stutter on supported devices and reduced-motion alternate. Do not claim precise Hz/FPS guarantee on untested hardware.

## Spatial continuity and showroom truth
The user should understand *where* they are at all times (floor number, unit number, room, compass/orientation if verified, breadcrumb). Object selection highlight maps to material ID and QA provenance. An interior claimed to be 3D free-walk is actual navigable geometry, not a still or rotating image. Panoramic still alternative clearly labeled. Representative renders must not deceptively reflect unrendered custom finishes.

## Mode-specific acceptance tests
- Start Cinematic -> pause in bedroom -> enter Free Walk -> exit -> resume tour from correct chapter; finish choices remain.
- Property Explorer -> floor F04 -> U04A -> material switch -> Guided Tour -> edit same living room; persisted exact surface.
- Guided Tour on iPhone in portrait -> Rotate device -> use gestures; no viewport loss/no scroll trap.
- Free Walk from doorway: repeated wall collisions, doorway travel, lift F04->F10, touch joystick optional; no clipping or uncontrolled movement.
- 2D Lite mode no-WebGL: select unit, gallery, inspect materials, finish board, creator contact, Arabic/English, deep link; all functional.
- Cinematic on reduced-motion: user-directed short still transitions, subtitles intact and skip operational.
