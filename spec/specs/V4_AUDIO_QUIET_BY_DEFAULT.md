# V4 — AUDIO, SILENCE, CONSENT AND RESPECTFUL SOUND DESIGN (MANDATORY)

## 1. Product promise
This experience is SILENT on every first load and every new page load, including return visits. Do not infer permission to play audio from general navigation clicks, selecting a property, selecting language, pressing Start Tour or loading a video. Explicitly turning on an audio control is the ONLY activation. Sound is never required to understand the building and MUST NOT consume noticeable network/CPU/GPU resources while muted.

## 2. One authoritative state machine
- `audio.masterEnabled` default FALSE on every full navigation/reload/new tab. `audio.userOptedInThisPageLoad` false until clear direct sound-control action. In-app SPA routes and changing floor/room/mode do not reset selected on/off state unless the user mutes it; full reload always starts OFF. Never auto-enable from saved storage or browser preference. Existing V2 `ambientSoundEnabled` is deprecated and MUST be removed/migrated to new audio controller.
- `audio.muted` is the only global master mute authority; avoid multiple racing React states or per-scene auto-start scripts. Initial `masterEnabled=false` and `muted=true`. Unmuted user gesture sets masterEnabled=true, muted=false. Re-mute synchronously sets muted=true and stops/suspends ALL output, including background HTMLMediaElements and WebAudio buffers.
- Explicitly opt into selected channels: `music`, `ambience`, `effects`, `narration`, all set to false until user enables master. Once audio is enabled, recommend restrained channel defaults (ambience 0.20, effects 0.28, music 0.12, narration 0.50), with visible independent sliders 0..100. No channel at max by default. Never play loud click/beep on enabling.
- On `visibilitychange` hidden, audio pauses/suspends and does not surprise user when returning; resuming sound requires an explicit user action after a hidden/background interruption. If media play promise rejects (NotAllowedError, etc.), remain muted and non-crashing, show nonmodal localized explanation.
- Strict on/off controls persist in one place: header accessible sound icon on all screen sizes, small control on cinematic overlay, Settings > Sound. Muted icon and text 'Sound Off'/'الصوت مطفأ' etc; do not use color alone. Accessible state `aria-pressed`, localized labels/tooltip, keyboard Space/Enter. 44px tap size, clear focus. Quick sound mute action must work during frame hitch, tour pause, loading screens, fullscreen, WebGL context-loss and Lite fallback.

## 3. Sound aesthetics
- If approved, use an original, unobtrusive audio palette: subtle UI feedback, gentle footsteps only in free walk, tasteful daylight/night ambience, optional guided tour narrative captions. NO looping 10-second royalty-free cliché; NO mandatory intro music; no abrupt stingers at camera transitions; no distracting door creaks/echoes, no surprise thunder or whistling. If ambient SFX tied to season/weather use asynchronous fades (150–400ms) and rate limit; weather change never overrides global mute.
- No geolocation/microphone permissions required. Audio tour is not a listening test. Narration has captions/transcript in FOUR languages, including accessible captions for videos, independent of audio state and optional language-aware voice only if licensed and high quality. Bad or absent voice > omit narration, keep written captions. Never pronounce place names or material safety data with guessed phonemes and claim perfect quality.
- Do not play audio assets remotely on default load: split chunks by tour/scene, wait for opt-in then fetch, cap cache, short loop seamless, compressed lightweight formats with fallback; full silence must be possible even if code for channels is loaded. Do not use music from copyrighted movies/commercial recordings without license. Audio ledger records source, commercial rights, duration and loop status.
- Minimize energy and battery cost: stop WebAudio scheduling/3D positional audio updates when muted or hidden; remove stale sources/listeners; app disposal must dispose AudioContexts and release streams on unmount.

## 4. Edge cases
- VoiceOver/TalkBack accessibility speech is system-controlled: master mute silences only WEBSITE audio, never OS/screen-reader narration. Focus and feedback must work without site audio.
- Video preview may autoplay if permanently muted and user-requested, but never with sound; `playsInline`, no unexpected full-screen switch. Cinematic Tour with sound off MUST remain fully legible through subtitles and visible chapter names.
- Tour controls (pause/restart/skip), language/quality/mode changes, browser history, media interruptions and screenshot export MUST NOT restart sound.
- Treat microphone use, push notifications, external speech APIs and voice assistants as separate opt-in product capabilities; default NONE.

## 5. Validation
Unit tests for initial mute and opt-in state, component tests for mute from EVERY view, browser tests Chrome/Firefox/Safari/iOS emulation and real iOS if available; automation should intercept `play`, `AudioContext.resume`, `fetch *.mp3/*.ogg`, speakers. Starting load without explicit audio opt-in must produce ZERO audible website output and ideally ZERO audio asset transfers. Browser gesture restrictions must be handled as failure states. Console errors or unhandled promise rejections prohibited. Audio button remains reachable in Lite mode.
