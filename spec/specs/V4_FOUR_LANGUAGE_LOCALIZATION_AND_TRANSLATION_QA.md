# V4 — COMPLETE 4-LANGUAGE SYSTEM AND TRANSLATION RELIABILITY

## 1. Locales and non-negotiable behavior
The primary source copy and first-visit URL/page is Iraqi-friendly professional **Arabic (ar-IQ, RTL)**, NOT an English-first dashboard. Supported secondary locales are **English (en, LTR)**, **Central Kurdish/Sorani (ckb-IQ, RTL)** using Arabic-derived Kurdish script used by many in Iraq's Kurdistan region, and **Simplified Chinese (zh-Hans, LTR)** suitable for Chinese-speaking visitors. Kurmanji (ku-Latn) is a DIFFERENT variety and not a substitution. If ever adding Kurmanji in the future, make it a separate language, script and review flow. Use locale-aware display names in native script: العربية | English | کوردی (سۆرانی) | 简体中文.

Arabic must have good Iraqi audience tone and engineering terminology (modern professional Arabic rather than casual machine slang); preserve marketing refinement. Chinese must be locally natural, not literal character-by-character translation. Kurdish Sorani must be written by someone who knows that dialect's script (ڕ, ڵ, ۆ, ێ, ە, etc.), correct keyboard/typography, NOT borrowed Persian or Arabic words where natural Kurdish technical terms exist. Keep English technology terms where customary and properly directional-isolated. Brand NAKHLA RESIDENCE is a brand; translations/localized script representations must be intentional and approved, never inconsistent across headers, PDFs and logos.

## 2. Scope inventory—every visible string (NO exceptions)
Hero, navigation, switcher, icons tooltips and aria labels, mode descriptions, progress bars, onboarding and skip, splash/loading/queued/failed states, model fallback, 3D hotspot text, floor/unit/room labels, descriptions, dimensions, material and package glossary, supplier placeholders, demo and data disclaimers, SEO/OG/meta, floor availability, Material Studio, price warnings, currency/units, weather and all four seasons, audio channels and volume labels, free walk help and collision errors, X-Ray/isolated floor, screenshots/photo licensing labels, gallery proof/selection mismatch notices, local save/share/QR, failed upload/save events, contact CTA, creator rights/copyright, privacy and form copy, tooltips/hints, access keys, error boundaries, accessibility live regions, keyboard shortcuts and PDF export; do not hard-code untranslated English in 3D canvas/GSAP timelines. Structured material descriptions and any future backend content require content localization too, not just 35 seed strings.

## 3. Architecture contract
- Single shared localization service; structured ICU MessageFormat or equivalent evaluated, versioned dictionary. Never string-concatenate translated sentences around variables or mix arbitrary `innerHTML` and translations. Typed localization keys generated/enforced; `Intl` for number, currency, dates and units; sanitize interpolated values; pluralization for rooms, floors, photos, guests, etc. Handle zero/one/two/plural differences correctly, especially Arabic.
- Use HTML `<html lang="ar-IQ" dir="rtl">` initially; on switch set accurate `lang` and `dir` at document root and main content, update tab title, metadata, accessible labels, page route, and PDF locale; use semantic `dir="auto"` or bdi/isolates for English technical terms, phone numbers, URLs and product codes embedded in RTL. LTR diagrams/camera coordinate overlays stay physically consistent; directional icon arrows and breadcrumbs should mirror logically, NEVER flip the 3D model or viewer camera itself. JSON IDs and room IDs stay fixed.
- Suggested locale route prefix `/ar/`, `/en/`, `/ckb/`, `/zh/`; resolved locale mapping to ar-IQ/en/ckb-IQ/zh-Hans; first-load default `/ar/` unless visitor manually selects another. Preserve selected locale through in-app navigation and subsequent visits if desired, but NEVER override an explicit URL locale. Detect unsupported locale -> default Arabic, not 404. Remember selected locale separate from audio preferences. Switching language while standing in F04/U04A/living keeps apartment, selected material, lighting/weather, current tour progress bookmark, camera pose and mute state; do not reinitialize Three.js or WebGL context. Language may influence content layout but not semantic state.
- Use accessible, bundled/subset fonts with complete Arabic/Sorani glyph support and Simplified Chinese glyph support. Verify weight, shaping, line height, hyphenation, punctuation, emoji fallback, button width and focus rings in Safari/Chrome/Firefox Android/iOS. Use reliable font licenses and avoid huge global font packs; language-scoped subsets lazy loaded after first paint, fallback fonts without FOIT; avoid >3MB first-load CJK font payload by subsetting/appropriate fallback.
- Provide robust RTL grid/flex layouts with logical CSS (`padding-inline-start`, etc.), no clipped sidebars, no direction changes that break 3D scene or drag direction. Handle responsive UI and text expansion (English vs Chinese vs long Arabic / Sorani) at 320, 360, 390, 768, 1024 and 1440 widths with 200% browser zoom and dynamic text size. Touch targets 44px and clear hit areas. Independent scroll in panels must not conflict with 3D touch gestures.
- Locale-aware unit formatting for `m²`, `cm`, °C, time of day, level numbers, and dates. Never numerically alter measured areas or quote fabricated architectural precision. Latin email/tel/WhatsApp markup stays valid in all locales and correctly isolated.

## 4. Translation editorial workflow (do NOT hallucinate perfection)
A. Inventory all message keys in static UI, dynamically generated text and server data; make ALL four locale dictionaries key-complete. Mark legacy strings needing rewriting. Define canonical Arabic termbase with approved English, Sorani and Chinese equivalents for building, floor, unit, room, balcony, material, finishes, waterproofing, lighting, gym, pool, sauna, restaurant, hookah/shisha lounge, demo project, copyright, creator, unavailable and request information. Preserve distinctions between residential floor, functional floor and building floor number (G, F01..F11).
B. First draft can be by Claude/MT but must carry explicit provenance and `reviewStatus='DRAFT_UNVERIFIED'`. Native language editors/reviewers with domain context must validate EACH string, then independently check HIGH-RISK statements (legal/privacy, availability, accessibility instructions, measurements, cash/price, environment claims, health/safety, shisha rules). If reviewers are not accessible, produce exact review-ready bilingual term sheets, `REVIEW_REQUIRED` flag in QA, and do not pretend validation happened. Do not post sensitive project files to 3rd-party translation APIs without authorization.
C. Review in contextual screenshots, not just a spreadsheet; check localization in actual 3D floor/unit detail, materials, 4 camera modes, audio control and PDF output. Back translation and pairwise comparisons are optional supportive heuristics but not substitutes for native review.
D. CI must fail on missing/extra/unreachable keys, falsy placeholders, untranslated UI English leftovers (where not intentional brand/product), HTML escape or ICU syntax errors, wrong tokens, truncation/ellipsis of important terms, plural and gender violations, mismatched glossary entries, key collisions, duplicate locale paths, untranslated chart labels or SEO metadata. Integration tests verify state survives locale change, tab order, locale URL, rtl/ltr flips, no changed floor id or material mapping, and no accidental sound unmute.
E. Do not mark a locale `APPROVED` before documented reviewer name/role, review date, text/catalog version hash, screenshot proof, and second-person review for legal/safety strings. If unapproved by release, disclose clearly to owner; a private concept demo can include draft locales with accurate caveat, but do not label production-ready.

## 5. User-centered enhancements
- Language menu uses native labels and abbreviated locale codes; always visible in header, in fullscreen Explorer via Info/Settings, accessible with keyboard/screenreader. No flags as language icons (flags represent countries, not languages). Preview translated tour chapters and audio mute toggle before applying.
- Language transition should be instantaneous and should not create reload, recompile 3D models or restart cinematic tour; no moving camera during a language change. Persist chosen language for later pages but don't force it on explicit locale URL.
- In 2D Lite mode all interactive explanatory text is equally localized, so lower-spec visitors are not second-class. Localize skeleton and retry descriptions; no strange untranslated technical errors shown directly to customers.
- For public pages add `hreflang` alternates if indexing is enabled, canonical URL policy and localized sitemap/metadata; don't duplicate a real building claim in SEO.

## 6. Non-negotiable verification
4-language screenshot sweep at mobile/tablet/desktop in light/dark or key sky themes; screen-reader auditing for ar and ckb RTL; PDF documents checked visually with valid embedded fonts and not broken Unicode; numeric formatting test at every locale and in mixed-script strings; CJK font-load weight and cache tests; voice/media mute remains off during locale switch. A build with untranslated strings is not ready. If native reviewer unavailable: cannot claim 'mistake free translations' regardless of automated test count.
