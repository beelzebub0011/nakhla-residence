# V7 ENGINEERING QUALITY GATES — NEVER TRADE RELIABILITY FOR SPECTACLE

## Binding priorities and non-goals
The real product is a fast browser-based interaction, NOT a portfolio of unrelated AI images or videos. Keep four top-level sections Explore, Tour, Design, Amenities and a contextual Nakhla AI helper. The building has G + residential F01–F09 (two apartments each) + F10 wellness gym/spa/pool + F11 dining/cafe/separate shisha proposal. All dimensions are conceptual until explicitly validated. No regulations compliance or certification claims. The existing 550 unexecuted QA cases and all prior obligations remain.

### GATE 1 — Architectural source-of-truth and spatial traceability (P0)
- Define a canonical metric coordinate system, right-handed axes, consistent world origin, floor-to-floor levels, structural bays, core boundaries, doors/windows and georeference placeholder. Model architecture via authored parameter objects, CAD/BIM where possible, and deterministic Blender build scripts rather than ad hoc eye-balling.
- Export a floor-zone-room-surface graph. Every UI selector ID and Nakhla AI fact resolves to the same catalog item; each GLB mesh uses stable semantic IDs (not array indices). Generate 2D plans, 3D cutaways, dollhouse scene and room metadata from the same dimensions and transforms where feasible.
- Reconcile GFA, NFA and usable room areas with explicit conventions. Use polygon computations for floor areas, unit and room bounds, and signed-off geometry evidence. Distinguish approximate concept area from measured designed area; never assert as-built dimensions. No measured volume/area until geometry verification.
- Check unit-to-floor, room-to-unit, door adjacency, stairs/lift alignment across all 12 levels, stair landings, shaft stacking, collision hulls, balcony access, pool load sensitivity, restaurant vent/service routes, privacy and realistic elevations. Require qualified engineer review for actual construction.
- Produce geometry audit JSON/CSV mapping semantic ID => model node, plan polygon/area, transform, source, verified flag, validation timestamp. A user pointing to a ceramic floor should yield current catalog material, not an unrelated hallucinated sample.
- Automated assertions (not merely screenshots): building 12 levels and 18 units; child-to-parent consistency; no duplicate semantic IDs, no rooms outside apartment shell, no floor mismatch, collision coverage; all dimensional claims derived from audited authored geometry; error thresholds documented for renders-vs-metadata.

### GATE 2 — Physically plausible materials, architecture and lighting (P0)
- Use glTF 2.0 PBR workflow (roughness, metallic, normal, AO, realistic texel density) and Blender Principled BSDF with energy-consistent real-world scale. Set correct color management across Blender to WebGL; verify material tone in neutral 6500K and warm indoor scenes; avoid clipping whites, glossy concrete, impossible sharp reflections, tiled noisy normals, or self-emission masquerading as realistic lights.
- Use genuine plausible material dimension references: 60×120 porcelain displays correct 600×1200mm geometry and grout spacing; wood grain correct scale/direction, stone slab seams, glass physical transmission and shading; do not claim brand, durability or supplier unless validated.
- Verify shadows, contact/AO subtleties, reflection plausibility, correct handedness, railings, joints, thresholds, door hinges, floor interfaces, real-world heights and avatar-eye viewpoint. Match each 2D plan opening with a 3D opening.
- Physically based sun direction when actual site orientation and coordinates provided; if approximate, label as SIMULATED not actual proof of solar exposure. Seasonal rain, haze, dust shall be believable but degrade gracefully on mid/low devices.
- Render golden-master comparison images for at least exterior midday/dusk/night; Type A living/kitchen/bedroom/bath/balcony; F10 pool/gym; F11 restaurant/lounge; compare camera-matched 3D screenshot and Blender outputs. Document differences and approved target quality tier.
- Generated AI imagery is VISUALIZATION ONLY until matched to final architecture. Every gallery item records `derived_from_actual_scene`/`concept_ai_generated`, match scope and eligible use; never label as actual photograph or exact selected materials if not true.

### GATE 3 — Performance, predictable loading, smart streaming (P0)
- Load HTML/navigation/floor list FIRST; do not block on the hero 3D asset or autoplay video. Interactions available in Lite/2D while 3D warms up in a separate path. Use lazy imports and scene-based chunks, progressive GLB/asset downloads, AbortControllers, request prioritization, cancellation and correct disposal of scene resources.
- Compression experiments: profile before/after GLB + meshopt or Draco, GPU texture KTX2/BasisU, geometry quantization, texture atlas, instancing, draw-call reduction, LOD, occlusion/frustum culling, limited shadow casters, pre-baked lightmaps when appropriate. Preserve material ID mappings and collision graph across LOD levels. Compression is not assumed beneficial without measured decode/transfer tradeoffs.
- No importing all twelve floors and all interiors on first load. One live hero/exterior scene; next-scene preload only when memory/network budget allows; reclaim all old scene textures, geometry, event handlers and render loops on navigation to reduce peak memory and heat.
- Adaptive quality OFF/LITE/LOW/BALANCED/HIGH/ULTRA; derive from real feature support and observed FPS/frame time, battery preference, motion preference and memory stability, not UA substring alone. Cap DPR/pixel count; throttle or suspend rendering when idle/tab hidden; never constantly render idle 60fps purely for ambience. Allow manual override and preserve semantics.
- Candidate budgets, not guaranteed: on adequate mobile 4G, aim shell interactive with LCP <=2.5s, INP <=200ms, CLS <=0.1 (p75 field targets). 3D initial scene should progressively appear with visible loading status; set measured budgets after hardware profiling. Target sustained 45–60 FPS balanced on capable desktop and >=30 FPS on representative midrange phone in normal walking; if not achievable, degrade detail before usability. Include low-end 20–30 FPS fallback. These FPS are project goals, NOT pre-certified metrics. Collect frame time p50/p95 and long tasks; test thermal throttling (5+ min walk), app memory, data transferred, GPU context resets and stale cache.
- Compress photos AVIF/WebP + responsive sizes, semantic alt, CSS aspect ratios. Separate cinematic trailer download from core visitor assets; never auto-download HD videos on cellular. Budget video sizes and use reduced-motion static posters.
- Serve build optimized over CDN with cache/versioned immutable asset hashes; robust cache invalidation after release, no stale GLB/data mismatch. Offline/small-network fallback must never expose fictitious 'ready' indicators.

### GATE 4 — Human-friendly camera, tours and non-nauseating navigation (P0)
- Shared single camera authority with cancelable state transitions. Preserve all selections when switching Cinematic, Guided, Free Walk, Property Explorer. Undo/back/reset, clear position, breadcrumbs and map button; escape key and no pointer-lock traps.
- Real-world eye height around 1.55–1.7m unless accessibility/seat view requires change; hard turn/pitch limits, acceleration and deceleration, proportional sensitivity, wall/door/balcony collision, no teleport into geometry. Prevent roll and violent FOV spikes, keep zoom/pan sane; tap-to-move on mobile, optional gentle virtual stick only when needed.
- Navmesh/path planning aligned with actual floors/doors/obstacles and verified height differences; verify stairs/elevator transition is accessible and does not clip walls. Restrict access to undeveloped/locked zones with accurate messaging, not invisible ghost barriers. Accessibility and motion-safe settings, reduced motion overrides autoplay and camera sweeps.
- Avoid motion stacking, runaway camera tween, accidental floor changes while gestures, touch scrolling trapped by canvas, controls under the keyboard or unsafe mobile safe areas. Touch targets >=44 CSS pixels when possible, focus-visible/keyboard navigation.
- Tour mode is optional and stoppable; if the visitor presses UI control, interrupted transition yields control smoothly without resetting selected floor, material overrides, environment or chat context.

### GATE 5 — Robust recovery & graceful degradation (P0)
- Catch WebGL context lost/restored and handle it using resource restoration procedures; test using supported context loss simulation where possible. A permanently broken canvas cannot block selectors, contact details, AI factual answers or available floor plans.
- Per-scene error boundaries, timeout and retry-with-backoff; loading state meaningful; prevent infinite spinner. On network interruption preserve the selection in memory/url; retry only idempotent GET operations; no repeated sales submit.
- On repeated graphics/decoder failure offer 2D Interactive Plan or image-based Lite with accessible navigation and all project facts. Mark the demo fallback honestly; do not call an image a live editable PBR scene.
- Support tab suspend/resume, resize and screen orientation, mobile back/forward, BFCache if feasible, hot reload, slow OS memory. Dispose resources and subscriptions; test no cumulative growth after 20 switch cycles.
- Loss of Higgsfield access, promo expiry or any other vendor cannot take down site. All generated promotional assets must be pre-exported and legally usable or removed.

### GATE 6 — Objective visual regression and all-locale QA (P0)
- Use Playwright (and appropriate WebGL/browser setup) for golden screenshot baselines with deterministic camera, locale, timezone, environment preset and seed. Test Arabic RTL, Sorani RTL, English LTR, Simplified Chinese LTR, glyph shaping, font fallback, safe areas and horizontal overflow on phone/tablet/laptop/desktop.
- Baselines cover default hero, dropdown/panel on touch, 10th/11th floors, walk mode, 3 material switches, 4 weather/season variants, 2D fallback, popup/error, AI bottom sheet, PDF UI and dark/bright environment contrast. Make auto-diff thresholds configurable, compare text positioning independently of 3D antialias noise.
- End-to-end tests should interact, not solely assert DOM. Assert material selection actually updates a GPU surface, scene transition preserves user state, audio OFF after reload, environment state preserved, 4 locale semantic equality, typed AI actions and no invented facts.
- Accessibility automated audit with manual keyboard/screen-reader checks; matrix Safari iOS, Chrome Android, desktop Chrome/Edge/Firefox and tablet Safari. Record actual device coverage and avoid reporting emulators as real devices.
- First-load, warm-load, slow 3G/4G, offline recovery, WebGL disabled, context lost, tab switching, keyboard open, orientation change, reduced motion and text zoom. Every P0 failure must be fixed or a clearly documented P0 release blocker, never silently waived.

### GATE 7 — Privacy-first operational quality monitoring (launch gate)
- Collect aggregated performance telemetry only on an opt-in or lawful privacy basis after user has approved deployment: Core Web Vitals, long-task/frame-time distribution, failed asset class, scene unload/load, crash rate, device tier, request latency and anonymized error signatures. NO webcam, microphone, raw chat, precise GPS, full personal IP or user text logging by default.
- Avoid leaking contact inquiries/AI content via analytics providers. No external trackers by default without consent and privacy policy. Use opt-in quality metrics UI where legally required. Retention period/consent/revocation explicit; developer dashboard password protected; no secrets in browser and throttled logging.
- Monitor cache version mismatches, image compression decode failures, stale asset 404s, CDN error trends and context loss; define rollback plan with known-good bundle and original floor/material metadata.
- Publish only with owner approval and documented release manifest/QA evidence. Have an operational checklist for data backup, versioning, accessibility and real-user support channels.
